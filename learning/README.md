# 用 Harness 方法学习 Harness

目标：学习者能诊断 AI 工作流程的一次失败，设计最小改进，用真实证据检查结果，并在新会话中接续工作。

这里采用中文讲义，固定教材版本见 [course.json](course.json)。14 讲的目标和 8 个迁移实验都在该文件中；原 Electron 项目仍按原说明另行验收。

## 每次学习怎样进行

1. **恢复**：助手读私有进度，确认上次卡点、当前目标和原文版本。
2. **说明**：用一个具体例子讲清本轮所需概念；根据用户基础补充，不先堆整章术语。
3. **应用**：用户完成一个短判断或小作品。可以查教材；关键判断由用户作出。
4. **检查**：检查者重新读取题目、标准和真实答案，按证据评价，不沿用讲解者的自我判断。可以由同一模型的新上下文承担；这仍不保证评价正确。
5. **修订**：有问题就只给一个定向提示，最多两轮。没有证据支持的问题，不为了显得严格而编造。
6. **交接**：保存实际回答、提示程度、判断依据、未解决项和下一步。需要用户作答时停下。

用户不用管理表格、手动整理日志，也不用先配置所有开发工具。助手承担这些工作。

## 什么才算本轮展示成功

验收看三件事：问题是否具体；改动是否回应问题；效果是否能由实际结果检查。

`demonstrated` 仅表示这次任务中出现了独立应用证据，不表示永久掌握。刚看完示范后的照抄不算；给过答案后，应换一个相近但不同的情境。后续反例暴露误解时可以重新检查。

`needs_recheck` 表示待复核，可有多个排队项，但一次只选择一个当前任务。先修单元待复核不会抹掉后续单元已有的历史成果；开始新单元前仍需确认先修状态。

原项目的 `verified` 另需真实运行命令、退出状态、输出和人工/独立复核。读完项目说明、完成学习版练习、静态检查成功，都不等于原应用已经跑通。

## 五部分如何落地

| Harness 部分 | 本学习项目中的作用 |
|---|---|
| 指令 | 根目录 AGENTS.md、本指南、每单元验收目标 |
| 工具 | 阅读原文、记录答案、检查状态；编程项目才增加运行工具 |
| 环境 | 固定教材版本，确认资料可读、练习可完成；Python 检查器无第三方依赖 |
| 状态 | 私有 Harness_Learning_State.json；示例文件不代表真实进度 |
| 反馈 | 用户实际产物、按标准检查、定向修订和迁移验证 |

## 进度与私密性

在 ChatGPT 中，真实状态保存为用户私有的 `Harness_Learning_State.json`。开始时读当前版本，更新时替换同一文件。公开仓库只存规范、题目和 [示例状态](state.example.json)。

本地学习者可以把示例复制到仓库外的私有目录，再通过 `--state` 显式传给检查器。不要把真实记录提交到公开 Git。

## 怎么判断这套方法有没有帮助

先做两对、共四个难度相近的短任务；固定材料与判定标准，一对先用普通对话，另一对先用 Harness，减少熟悉顺序的影响。没有实际用户参与时，不填写实验结果。

只记录：需要重复解释旧信息的次数、新情境中的实际应用表现、用户总投入时间。耗时不明就记未知，不估造数字。由真实答案支撑结论，样本只说明该次观察。如果维护文档增加却没有帮助思考，就减少结构或修改练习。

## 检查与收尾

```sh
python3 learning/check.py
python3 learning/check.py --state /absolute/private/path/Harness_Learning_State.json
```

默认命令检查示例。指定私有状态时检查目标覆盖、当前任务、证据类型和审阅字段；成功仅表示记录结构有效。它不会阅读答案后自动评分，也不能证明外链当前可访问。

结束时更新同一私有记录中的 `handoff`：这次实际验证什么、仍缺什么、下一步做什么。缺少用户答案就保留 `awaiting_response`，不要生成替代答案。
